# Bank Pet (Java Middle Interview Demo)

Полноценный демо-банк на Spring Boot:
- клиент, счета, карты, транзакции;
- кошелёк цифрового рубля;
- AI Spending Guardian + LLM-анализ риска;
- NFC-платежи под капотом (без отдельного NFC-экрана);
- синхронизация истории из других банков;
- REST API + Web UI (Thymeleaf).

## Что обновлено
- Исправлен визуал фона: снова один плавный градиент (без «трёх полос»).
- Боковая панель с расширенными профилями характера агента:
  - `Сбалансированный`, `Дружелюбный`, `Строгий`, `Грубый`, `Хулиган`, `Пикми гёрл`, `Жена`, `Мать`, `Начальник`.
- Вкладка `Платежи` показывает:
  - количество отказов от импульсивных трат;
  - сумму сэкономленных денег на отменённых покупках.
- Кнопка отказа в popup имеет сине-зелёный градиент.

## Насколько реально обернуть NFC и конкретные карты банков?
Реально, но в production это делается через официальные платёжные контуры/SDK:
1. Мобильное приложение получает token карты/устройства (device token / network token).
2. Бэкенд работает через процессинг/шлюз (антифрод, лимиты, 3DS, риск-движок).
3. Для разных банков — либо open API/партнёрские интеграции, либо собственный эквайринг.

Итог: **архитектурно возможно**, но нужна юридическая и техническая интеграция с платёжной инфраструктурой, просто «обёрткой поверх любого банка» без договорённостей это не делается.

## Насколько реально подключение цифрового рубля?
Тоже реально, но зависит от официального API/регламента платформы ЦБ/провайдера:
- нужен сертифицированный контур интеграции;
- KYC/AML и аудит операций;
- idempotency, события статусов, reconciliation;
- юридическое подключение и sandbox/прод-доступ.

То есть в pet-проекте мы правильно моделируем архитектуру, а в бою подключение требует внешней платформы и комплаенса.
