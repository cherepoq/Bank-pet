# RentFlow MVP

> **Перед покупкой сервера и домена:** откройте [`HOSTING.md`](HOSTING.md). Там есть рекомендуемая конфигурация, ориентиры бюджета, ссылки на Timeweb Cloud, Selectel и Beget, а также пошаговый запуск HTTPS.

Мобильное PWA для управления арендой. Интерфейс построен вокруг ежедневных сценариев арендодателя и арендатора: сроки, платежи, документы и видеофиксация состояния объекта.

## Что работает в MVP

- переключение ролей «Арендодатель» / «Арендатор»;
- обзор ближайшего платежа и обратный отсчёт;
- долгосрочные и посуточные объекты;
- добавление аренды с сохранением данных на устройстве;
- отметка платежа;
- ручной учёт полной или частичной оплаты без перевода денег через приложение;
- дополнительные начисления и зашифрованные чеки от арендатора или арендодателя;
- загрузка и поиск файлов;
- раздел видеоосмотров;
- адаптивный интерфейс и установка как PWA.

## Безопасность локального MVP

- Загруженные документы и видео шифруются в браузере алгоритмом AES-256-GCM перед записью в IndexedDB.
- Ключ создаётся Web Crypto API как неизвлекаемый (`extractable: false`) и хранится отдельно от зашифрованных объектов.
- Для каждого объекта генерируется уникальный 96-битный IV; подмена шифротекста обнаруживается GCM-аутентификацией.
- Изображения больше 350 КБ уменьшаются до 1920 px и конвертируются в WebP до шифрования. Видео ограничено 100 МБ; транскодирование оставлено серверному media pipeline, так как браузерное перекодирование нестабильно и сильно расходует батарею.
- CSP запрещает сторонние скрипты, плагины, внешние подключения и отправку форм на другие origins.

Это защита локального MVP, а не замена production-бэкенду. Платёжные реквизиты нельзя хранить во фронтенде: будущая платёжная интеграция должна использовать токены лицензированного провайдера, 3-D Secure и PCI DSS-контур. Production-файлы должны шифроваться envelope encryption через KMS, а доступ — проверяться сервером и фиксироваться в неизменяемом audit log.

### Как устроен учёт аренды

RentFlow сейчас **не переводит деньги и не подключается к банковскому счёту**. Пользователь вручную задаёт сумму и дату, отмечает полную или частичную оплату, добавляет корректирующее начисление и при желании прикладывает чек. Остаток пересчитывается на устройстве, а чек шифруется в локальном vault. Такой сценарий позволяет проверить продукт без хранения карточных данных. Настоящий платёжный сервис остаётся отдельным будущим модулем.

## Запуск

### Быстрый просмотр только фронтенда

Для этого варианта не нужны Java, Maven или Docker:

```bash
./scripts/static_preview.sh
```

Откройте `http://localhost:4173`. Другой порт можно указать так: `PORT=3000 ./scripts/static_preview.sh`.

Нажмите кнопку **⚙** в правом верхнем углу приложения, чтобы прямо в браузере изменить демонстрационную сумму, количество дней, название объекта и основной цвет. Настройки сохраняются локально и не меняют файлы проекта.

### Docker

```bash
./scripts/run_docker.sh
```

Откройте `http://localhost:8080/app`.

### Maven

```bash
./scripts/local_preview.sh
```

## Публичный preview через GitHub Pages

В репозитории настроен workflow `.github/workflows/pages.yml`. После попадания изменений в ветку `main`:

1. Откройте **Settings → Pages** в GitHub.
2. В поле **Source** выберите **GitHub Actions**.
3. Откройте **Actions → Deploy RentFlow preview to GitHub Pages** и дождитесь зелёного статуса.
4. Ссылка появится на странице deployment и будет иметь вид `https://<username>.github.io/<repository>/`.

Workflow также можно запустить вручную кнопкой **Run workflow**. Относительные пути ресурсов позволяют preview работать как в корне домена, так и в подпапке GitHub Pages.

## Архитектура

Существующий runtime использует Spring Boot 3 и Java 21. Клиент MVP находится в `src/main/resources/templates/dashboard.html`, стили — в `static/css`, сценарии — в `static/js`.

Целевая production-архитектура может быть перенесена на ASP.NET Core без изменения UX-контрактов. Для production-релиза потребуются PostgreSQL, объектное хранилище, OIDC/OAuth, серверная авторизация по ролям, KMS для ключей, шифрование файлов и аудит операций. Текущий MVP не выдаёт браузерное `localStorage` за защищённое серверное хранилище.

### Серверное хранилище

Backend предоставляет `POST /api/media`, `GET /api/media`, `GET /api/media/{id}` и `DELETE /api/media/{id}`. Файлы проверяются по разрешённому MIME type, сигнатуре содержимого, квоте и размеру, получают SHA-256, шифруются AES-256-GCM с уникальным IV и сохраняются вне web-root. Видео на production-образе транскодируется FFmpeg в H.264/AAC MP4, очищается от metadata и оптимизируется для потокового старта.

Для локального запуска production-контура задайте секреты и используйте Docker Compose:

```bash
export DATABASE_PASSWORD='change-this-database-password'
export MEDIA_ENCRYPTION_KEY="$(openssl rand -base64 48)"
export MEDIA_API_TOKEN="$(openssl rand -hex 32)"
docker compose up --build
```

Compose запускает PostgreSQL, persistent volume для зашифрованных медиа и приложение с профилем `prod`. Значения по умолчанию предназначены только для статического preview. Перед публичным запуском shared API token необходимо заменить полноценным OIDC/JWT и проверкой прав на каждый объект аренды.

Frontend использует серверную загрузку, когда после авторизации в `sessionStorage` присутствует `rentflow-api-token`; иначе остаётся локальный зашифрованный vault. Это переходный контракт до подключения экрана входа.

GitHub Actions workflow `RentFlow CI` проверяет JavaScript, Android release-конфигурацию, запускает backend-тесты, собирает production JAR и публикует его как CI artifact.

## Что нужно для домена

1. Зарегистрированный домен или поддомен, например `app.rentflow.ru`.
2. VPS с публичным IPv4, открытыми входящими портами TCP 80/443 и UDP 443.
3. DNS `A`-запись домена на IP сервера; при наличии IPv6 также `AAAA`.
4. Переменные `DOMAIN`, `DATABASE_PASSWORD`, `MEDIA_ENCRYPTION_KEY`, `MEDIA_API_TOKEN` и `ANDROID_CERT_SHA256`.
5. Запуск `docker compose --profile edge up -d --build`. Caddy автоматически получает и обновляет TLS-сертификат.
6. Проверка `./scripts/domain_check.sh app.rentflow.ru`.

Не включайте CDN proxy до первого успешного получения сертификата. Для Google Play домен должен стабильно отдавать `/app`, manifest, privacy policy, account deletion page и `/.well-known/assetlinks.json` без редиректов на авторизацию.

Сравнение вариантов VPS, ориентиры бюджета и последовательность покупки находятся в [`HOSTING.md`](HOSTING.md). Шаблон production-переменных — `.env.production.example`.
